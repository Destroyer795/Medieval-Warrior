# Setting up Medieval Warrior

Everything you need to get the project running exactly as intended, from a clean machine.
If you only want to **play**, sections 1–4 are enough. Sections 5–8 are for working on it.

---

## 1. What you need

| Tool | Version | Notes |
|------|---------|-------|
| **Unity Hub** | latest | <https://unity.com/download> |
| **Unity Editor** | **6000.3.2f1** | Any 6000.3.x opens it. Install via Hub → *Installs* → *Install Editor* (use the *Archive* tab for the exact version). Only the default modules are needed; add *Windows Build Support (IL2CPP)* only if you want IL2CPP builds. |
| **Git** | any | On Windows, run `git config --global core.longpaths true` once – some asset-pack paths are long. |
| Python 3.10+ | optional | Only to regenerate textures, UI art or audio (section 7). `pip install numpy scipy pillow` |

Disk: ~1.5 GB after the first import (the `Library/` cache Unity builds locally).

## 2. Get the project

```bash
git clone https://github.com/Destroyer795/Medieval-Warrior.git
```

Keep the folder path reasonably short (e.g. `C:\dev\Medieval-Warrior`).

**All game assets are in the repository** – castle pack, knight and zombie models, generated
terrain, meshes, prefabs, textures, fonts, UI art, music and sound effects. Nothing has to be
downloaded or generated by hand to play.

## 3. Open it in Unity

1. Unity Hub → *Projects* → *Add* → *Add project from disk* → pick the cloned folder.
2. Open it with **6000.3.2f1**. The first import takes **5–15 minutes**
   (it builds `Library/`, compiles scripts and downloads packages).
3. Packages are listed in `Packages/manifest.json` and come from the Unity registry. The only
   non-default one is **Post Processing (`com.unity.postprocessing` 3.5.4)** – it provides the bloom,
   ambient occlusion and colour grading.

### If the package download stalls
On slow or filtered connections the Post Processing download can hang ("Resolving packages").
Workaround:
1. Close Unity.
2. Download the package tarball:
   <https://download.packages.unity.com/com.unity.postprocessing/-/com.unity.postprocessing-3.5.4.tgz>
3. Extract it; inside is a `package` folder. Copy that folder to
   `Packages/com.unity.postprocessing/` (so `Packages/com.unity.postprocessing/package.json` exists).
4. Reopen the project. Unity uses it as an *embedded* package.
   That folder is git-ignored. If Unity rewrites `Packages/packages-lock.json` to an `"embedded"`
   entry for it, **don't commit that change**.

### First-open console messages you can ignore
- `ArgumentOutOfRangeException ... UnityEditor.Search.SearchDatabase` – Unity's search indexer on a
  project without `UserSettings/`. Harmless; it goes away after the first session.
- `The tree ... must use the Nature/Soft Occlusion shader` – our trees are never billboarded, so
  this warning does not matter.
- `warning CS8785: Generator 'AttributeBasedFieldGenerator' failed` – from a Unity package.

## 4. Play

- Open **`Assets/Scenes/MainMenu.unity`** and press **Play**.
- Or open **`Assets/Scenes/Semi-Final.unity`** and press Play to jump straight into a match
  (the mode and difficulty last chosen in the menu are used).
- `Assets/Scenes/Background.unity` is the castle world; the other two scenes load it for you.
  Don't press Play in it directly.

Controls are listed in the README and in the in-game *How to Play* page. A gamepad works too.

## 5. Build the game

- Menu **Medieval Warrior → Build Windows Player** → `Builds/Windows/MedievalWarrior.exe`
- or *File → Build Profiles → Windows → Build*. The scene list is already set
  (`MainMenu`, `Semi-Final`, `Background`).
- `Builds/` is git-ignored – share builds as a zip, not through git.
- A built game can check itself:
  ```
  Builds/Windows/MedievalWarrior.exe -autotest -screen-fullscreen 0 -screen-width 1280 -screen-height 720 -logFile autotest.log
  ```
  It plays two short matches without input and exits; `autotest.log` ends with
  `[AUTOTEST] RESULT PASS` and an FPS line.

## 6. Test before you push

**Medieval Warrior → Run Smoke Test** (about 3 minutes). It walks every menu, plays all three
modes, spawns every zombie type, checks movement and animation, the archer pose, arrows, pickups,
boons, pause, victory and defeat, and that the houses sit on the terrain. Results and ~30
screenshots go to `Temp/SmokeShots/` – `report.txt` must start with `PASS`.

From the command line (Unity closed):
```
"<Unity>/Editor/Unity.exe" -batchmode -projectPath . -executeMethod SmokeTest.RunBatch -shotDir Temp/SmokeShots -logFile smoke.log
```
Exit code 0 means everything passed. The test never touches your saved high scores or feats.

## 7. Where the assets come from (and how to regenerate them)

| Asset | Where it lives | Made by |
|-------|----------------|---------|
| Castle, houses, walls | `Assets/Advance Studios/` | *Medieval Castle* (Advance Studios, free Asset Store pack) |
| Knight + animations | `Assets/Toon_RTS_demo/` | *Toon RTS* demo (Polygon Blacksmith) |
| Zombies + animations | `Assets/Zombie/` | *Free Zombie* pack |
| Terrain textures, sky | `Assets/Environment/Textures/` | Poly Haven (CC0), graded by `Tools/ArtPipeline/terrain_textures.py` |
| Graded castle textures | `Assets/Environment/Textures/Castle/` | `Tools/ArtPipeline/castle_and_knight.py` |
| Knight recolour masks | `Assets/Resources/Customization/` | `Tools/ArtPipeline/castle_and_knight.py` |
| Grass and flower cards | `Assets/Environment/Textures/Grass*.png`, `Flowers*.png` | `terrain_textures.py` / `ui_art.py` |
| UI sprites | `Assets/Resources/UI/` | `Tools/ArtPipeline/ui_art.py` |
| Sound effects, music | `Assets/Resources/Audio/` | `Tools/ArtPipeline/sfx.py`, `extra_audio.py` |
| Fonts | `Assets/Resources/Fonts/` | Cinzel Decorative, MedievalSharp (SIL OFL) |
| Terrain, trees, rocks, foundations, crates, bow/arrow/potion meshes, NavMesh, zombie animator | `Assets/Environment/Generated/`, `Assets/Resources/Prefabs/`, `Assets/Animations/ZombieBrain.controller` | the **Rebuild Environment** tool |

### Regenerating the world
**Medieval Warrior → Rebuild Environment** rebuilds the terrain (mound, rolling ground, building
pads), paints it, places grass, trees, rocks, foundations, supply crates, banners and smoke, sets up
lighting and post-processing, re-seats every building on the ground, rebakes the NavMesh and
rebuilds the menu scene. It takes a few minutes and is deterministic.
It **replaces** the `Environment` object and everything in `Assets/Environment/Generated` –
make world changes in `Assets/Editor/EnvironmentBuilder.cs` / `GameplayBuilder.cs`, not by hand.

### Regenerating textures / UI / audio (optional)
See `Tools/ArtPipeline/README.md`. Short version:
```bash
pip install numpy scipy pillow
python Tools/ArtPipeline/download_sources.py sources
python Tools/ArtPipeline/terrain_textures.py sources Assets/Environment/Textures
python Tools/ArtPipeline/castle_and_knight.py .
python Tools/ArtPipeline/ui_art.py Assets/Resources/UI
python Tools/ArtPipeline/sfx.py Assets/Resources/Audio
python Tools/ArtPipeline/extra_audio.py Assets/Resources/Audio
```
Then run **Rebuild Environment** in Unity.

## 8. Troubleshooting

| Symptom | Fix |
|---------|-----|
| Pink / magenta materials | The Post Processing package or the project's shaders didn't import. Check *Window → Package Manager*; see section 3. Then *Assets → Reimport All*. |
| Clone fails with "Filename too long" | `git config --global core.longpaths true`, clone again to a shorter path. |
| Pressing Play in `Semi-Final` shows no world | `Background.unity` must stay in the build list and in `Assets/Scenes/`; `GameManager` loads it. |
| Zombies stand still | The NavMesh asset is missing: run *Rebuild Environment*, or check `Assets/Scenes/Semi-Final/NavMesh.asset` exists. |
| Text shows as squares | The fonts in `Assets/Resources/Fonts` are missing – re-pull from git. |
| Everything is very dark | You're looking at `Background.unity` alone (lighting lives in `Semi-Final`/`MainMenu`). Open one of those. |
| Huge diff after opening | You opened with a different Unity version. Discard and reopen with 6000.3.2f1. |

## 9. Working together

- Agree who is editing which scene; scene files merge badly.
- Gameplay is in `Assets/Scripts`, UI is built in code (`Assets/Scripts/UI`), the world comes from
  the builder – most changes never touch a scene.
- Run the smoke test before pushing. Commit the regenerated scenes/assets together with any builder
  change that produced them.
- Read `Docs/DEVELOPER_GUIDE.md` for how the systems fit together.
